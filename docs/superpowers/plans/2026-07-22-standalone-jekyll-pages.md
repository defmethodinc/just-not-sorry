# Standalone Jekyll and GitHub Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unmaintained `github-pages` gem with standalone Jekyll 4.4.1 on Ruby 4.0.6 and deploy the unchanged site through GitHub's native Pages artifact workflow.

**Architecture:** The `site/Gemfile` directly owns Jekyll, the existing minimal theme, and WEBrick. Root npm scripts generate dynamic site data, invoke the locked Jekyll build, and run a repository-owned Node artifact validator; GitHub Actions uploads that verified `_site` directory and deploys it only from `main`.

**Tech Stack:** Ruby 4.0.6, Bundler, Jekyll 4.4.1, jekyll-theme-minimal 0.2.0, WEBrick 1.9.2, Node.js 24, Node's built-in test runner, GitHub Pages Actions

## Global Constraints

- Keep Ruby pinned to exactly 4.0.6 in `site/.ruby-version`.
- Remove the `github-pages` gem completely; do not replace it with another compatibility bundle.
- Generate `site/Gemfile.lock` with `bundle install`, never `bundle update`.
- Do not add direct pins for transitive gems.
- Preserve all existing Markdown, Liquid templates, includes, images, theme behavior, routes, and `site/CNAME`.
- Pull requests build and validate but never deploy; only `main` deploys.
- Preserve unrelated user changes already present on `issue_197_upgrade_ruby`.

---

## File Structure

- `site/Gemfile`: direct maintained Ruby dependencies and Ruby-file declaration.
- `site/Gemfile.lock`: reproducible Ruby 4.0.6 dependency graph generated by `bundle install`.
- `site/test/validate-site.mjs`: reusable generated-artifact assertions plus command-line entry point.
- `site/test/validate-site.test.mjs`: isolated tests for successful and invalid artifacts.
- `package.json`: canonical site data, build, test, and validation commands; removes branch-publishing commands.
- `package-lock.json`: removes the npm `gh-pages` package and its transitive dependencies.
- `.github/workflows/website-publish.yml`: build, validate, upload, and main-only Pages deployment.
- `site/README.md`: local Ruby/Jekyll workflow and supported deployment description.
- `README.md`: root-level website build and publishing commands.

- [ ] **Step 3: Implement the minimal validator**

Create `site/test/validate-site.mjs` with:

```js
import { existsSync, readFileSync } from 'node:fs';
import { pathToFileURL } from 'node:url';
import { resolve } from 'node:path';

const REQUIRED_FILES = [
  'index.html',
  'phrases.html',
  'releases.html',
  'assets/css/style.css',
  'CNAME',
];

export function validateSite(root, expectedVersion, expectedPhrase) {
  for (const relativePath of REQUIRED_FILES) {
    if (!existsSync(resolve(root, relativePath))) {
      throw new Error(`Missing site artifact: ${relativePath}`);
    }
  }

  const index = readFileSync(resolve(root, 'index.html'), 'utf8');
  const phrases = readFileSync(resolve(root, 'phrases.html'), 'utf8');
  const css = readFileSync(resolve(root, 'assets/css/style.css'), 'utf8');
  const cname = readFileSync(resolve(root, 'CNAME'), 'utf8').trim();

  if (cname !== 'justnotsorry.com') throw new Error(`Unexpected CNAME: ${cname}`);
  if (!index.includes('Just Not Sorry')) throw new Error('Missing site title');
  if (!index.includes('/assets/css/style.css')) throw new Error('Missing theme stylesheet reference');
  if (!index.includes(`Site version ${expectedVersion}`)) throw new Error('Missing site version');
  if (!phrases.includes(expectedPhrase)) throw new Error('Missing generated warning phrase');
  if (css.trim() === '') throw new Error('Theme stylesheet is empty');
}

if (import.meta.url === pathToFileURL(process.argv[1]).href) {
  const [, , root, expectedVersion, expectedPhrase] = process.argv;
  validateSite(root, expectedVersion, expectedPhrase);
}
```

- [ ] **Step 4: Replace the website workflow**

Implement two jobs in `.github/workflows/website-publish.yml`:

```yaml
permissions:
  contents: read

jobs:
  build-website:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - uses: ruby/setup-ruby@v1
        with:
          bundler-cache: true
          working-directory: site
          cache-version: site-standalone-jekyll
      - run: npm run site:test
      - run: npm run site:build
      - run: npm run site:validate
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v4
        with:
          path: site/_site

  publish-website:
    if: github.ref == 'refs/heads/main'
    needs: build-website
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

Keep the existing path filters for `site/**`, `package.json`, `package-lock.json`, `src/warnings/phrases.json`, and the workflow itself.

## Deployment Prerequisite

Before merging, a repository administrator must set **Settings → Pages → Build and deployment → Source** to **GitHub Actions**. This is a one-time external setting; the workflow cannot safely infer or mutate it.
